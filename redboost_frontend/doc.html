01

Aperçu du Projet

RedBoost Platform est une application d'entreprise à trois niveaux, prête pour la production, offrant une API REST sécurisée, une SPA Angular moderne et une persistance MySQL. Elle centralise la gestion de programmes d'incubation, de sprints, de tâches, de coaching et de messagerie.

⚡

SPA Angular

Modules à chargement différé, PrimeNG, Tailwind CSS et authentification JWT

🌿

API Spring Boot

Points d'accès REST clairs avec une architecture en couches et Swagger UI

🗄️

Base de données MySQL

Persistance relationnelle via Spring Data JPA / Hibernate

🔒

Sécurité JWT

Authentification sans état avec contrôle d'accès basé sur les rôles

🔔

Firebase

Notifications push en temps réel et authentification sociale

03

Démarrage Rapide

1

Cloner le Dépôt

bash
git clone https://github.com/redstart-redboost/Redboost.git
cd Redboost
2

Créer la Base de Données

sql
CREATE DATABASE redboost CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'redboost_user'@'localhost' IDENTIFIED BY 'VotreMotDePasse!';
GRANT ALL PRIVILEGES ON redboost.* TO 'redboost_user'@'localhost';
FLUSH PRIVILEGES;
3

Configurer application.properties

Fichier : src/main/resources/application.properties. Les valeurs en rouge sont obligatoires et ne doivent jamais être committées dans Git.

application.properties
# ── Application ─────────────────────────────────────────────
spring.application.name=redboost
server.port=8087

# ── Base de données ──────────────────────────────────────────
spring.datasource.url=jdbc:mysql://localhost:3306/redboost?createDatabaseIfNotExist=true
spring.datasource.username=VOTRE_UTILISATEUR_DB
spring.datasource.password=VOTRE_MOT_DE_PASSE_DB
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.jpa.hibernate.ddl-auto=update
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect

# ── Upload de fichiers ───────────────────────────────────────
spring.servlet.multipart.enabled=true
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=20MB
# Développement local :
#file.upload-dir=uploads
# Production :
file.upload-dir=/var/app/uploads
file.upload.sprint-documents-dir=/var/app/uploads/sprint-documents
file.upload.activity-documents-dir=/var/app/uploads/activity-documents
file.upload.tache-documents-dir=/var/app/uploads/tache-documents

# ── JWT ──────────────────────────────────────────────────────
# Générer avec : openssl rand -base64 32
jwt.secret.key=VOTRE_CLE_JWT_BASE64_MIN_256_BITS

# ── Firebase ─────────────────────────────────────────────────
# Placer firebase-service-account.json dans src/main/resources/
firebase.credentials.path=classpath:firebase-service-account.json

# ── Google OAuth2 ────────────────────────────────────────────
google.oauth.client-id=VOTRE_GOOGLE_CLIENT_ID
google.oauth.client-secret=VOTRE_GOOGLE_CLIENT_SECRET
google.oauth.refresh-token=VOTRE_GOOGLE_REFRESH_TOKEN_LONGUE_DUREE
google.oauth.token-uri=https://oauth2.googleapis.com/token
google.oauth.organizer-email=VOTRE_EMAIL_ORGANISATEUR@gmail.com
google.email.user=VOTRE_EMAIL_GOOGLE@gmail.com
google.tokens.directory=tokens

# ── Google Drive ─────────────────────────────────────────────
google.drive.folder.id=ID_DU_DOSSIER_DRIVE_CIBLE
# Production :
google.drive.credentials.path=/home/redboost/config/google-oauth-credentials.json
google.drive.tokens.directory=/home/redboost/tokens
# Développement (décommenter) :
#google.drive.credentials.path=src/main/resources/google-oauth-credentials.json
#google.drive.tokens.directory=src/main/resources/tokens

# ── OAuth2 Provider Google ───────────────────────────────────
spring.security.oauth2.client.provider.google.authorization-uri=https://accounts.google.com/o/oauth2/auth
spring.security.oauth2.client.provider.google.token-uri=https://oauth2.googleapis.com/token
spring.security.oauth2.client.provider.google.user-info-uri=https://openidconnect.googleapis.com/v1/userinfo
spring.security.oauth2.client.provider.google.user-name-attribute=sub

# ── Chiffrement des messages ─────────────────────────────────
# Exactement 16 ou 32 caractères
encryption.secret.key=VOTRE_CLE_CHIFFREMENT_16_OU_32_CHARS

# ── Service IA ───────────────────────────────────────────────
ai.service.base-url=http://localhost:8000

# ── HTTP Client ──────────────────────────────────────────────
spring.http.client.connect-timeout=10000
spring.http.client.read-timeout=30000

# ── SSL — Production uniquement (décommenter) ────────────────
#server.ssl.key-store-type=PKCS12
#server.ssl.key-store=/etc/ssl/private/redboost.tn.p12
#server.ssl.key-store-password=VOTRE_MOT_DE_PASSE_KEYSTORE
#server.ssl.key-alias=redboost
#server.ssl.enabled=true

# ── Journalisation ────────────────────────────────────────────
# Développement : DEBUG | Production : passer à INFO
logging.level.org.springframework=DEBUG
logging.level.org.hibernate=DEBUG
logging.level.org.springframework.security=DEBUG
logging.level.org.hibernate.SQL=DEBUG

Sécurité Ne jamais committer de vraies clés dans Git. Utilisez des variables d'environnement ou un fichier .env listé dans .gitignore.

Structure du Projet

Backend (Spring Boot)

arborescence
backend/src/main/java/team/project/redboost/
  config/          → Sécurité, CORS, Swagger, Beans, Filtre JWT
  controller/      → Contrôleurs REST (@RestController)
  service/         → Logique métier (@Service), UserDetailsService
  repository/      → Dépôts JPA (@Repository)
  model/entity/    → Entités JPA (@Entity)
  dto/             → DTOs Requête / Réponse
  exception/       → Exceptions personnalisées

Frontend (Angular)

arborescence
frontend/src/app/
  core/
    services/       → auth.service.ts, api.service.ts
    interceptors/   → jwt.interceptor.ts
    guards/         → auth.guard.ts, role.guard.ts
  shared/           → Composants et modèles réutilisables
  features/         → Modules de fonctionnalités (lazy loading)
  environments/     → environment.ts, environment.prod.ts

Sécurité & Rôles

Flux d'Authentification JWT

1

POST des identifiants vers /api/Auth/login

L'email et le mot de passe sont envoyés au point d'accès d'authentification.

2

Spring Security valide via BCrypt

Les identifiants sont comparés au mot de passe haché en base MySQL.

3

Token JWT retourné

Un token d'accès signé est émis — expire dans 24h par défaut.

4

Le client envoie le token à chaque requête

L'en-tête Authorization: Bearer <token> est ajouté par l'intercepteur Angular.

5

JwtRequestFilter valide chaque appel

Le filtre s'exécute avant chaque contrôleur — rejette les tokens invalides ou expirés avec une erreur 401.

Pipeline CI/CD automatique Un simple git push sur main suffit. GitHub Actions build et déploie automatiquement le backend Spring Boot, le frontend Angular et le microservice IA Python sur le VPS OVH — aucune intervention manuelle requise.

Étapes détaillées

1

Checkout & Build JAR — redboost_backend/

Le runner clone le repo puis build le backend avec Java 17 (Temurin). Les tests sont skippés pour accélérer le pipeline.

workflow step
- uses: actions/setup-java@v4
  with:
    java-version: '17'
    distribution: 'temurin'
- run: mvn clean package -DskipTests
  working-directory: redboost_backend
# Produit : redboost_backend/target/*.jar
2

Install & Build Angular — redboost_frontend/

Node 24 est installé, puis npm ci installe les dépendances de façon reproductible (depuis package-lock.json), enfin npm run build génère le bundle de production.

workflow step
- uses: actions/setup-node@v4
  with:
    node-version: '24'
- run: |
    npm ci
    npm run build
  working-directory: redboost_frontend
# Produit : redboost_frontend/dist/sakai-ng/*
3

Setup SSH avec clé ed25519

La clé privée est injectée depuis les GitHub Secrets dans ~/.ssh/id_ed25519. Le fingerprint du VPS est ajouté à known_hosts via ssh-keyscan pour éviter toute interaction interactive.

workflow step
mkdir -p ~/.ssh
echo "${{ secrets.VPS_SSH_KEY }}" > ~/.ssh/id_ed25519
chmod 600 ~/.ssh/id_ed25519
ssh-keyscan -H "${{ secrets.VPS_HOST }}" >> ~/.ssh/known_hosts
🔑
Les 3 secrets GitHub suivants doivent être configurés dans Settings → Secrets and variables → Actions du dépôt.

4

Upload JAR → /home/redboost/

Le JAR buildé est copié sur le VPS via SCP. Il remplace le JAR précédent en place.

workflow step
scp -i ~/.ssh/id_ed25519 \
  redboost_backend/target/*.jar \
  ubuntu@51.91.253.146:/home/redboost/
5

Upload Angular dist → /var/www/html/

Le contenu de dist/sakai-ng/ est copié récursivement dans le répertoire servi par Nginx.

workflow step
scp -i ~/.ssh/id_ed25519 -r \
  redboost_frontend/dist/sakai-ng/* \
  ubuntu@51.91.253.146:/var/www/html/
6

Restart Spring Boot — redboost-prod.service

Le service systemd est redémarré via SSH pour charger le nouveau JAR.

workflow step
ssh ubuntu@51.91.253.146 \
  "sudo systemctl restart redboost-prod.service"
7

Upload & restart microservice IA — redboost-ai.service

Les fichiers Python du dossier ai_service/ sont copiés dans /home/redboost/ai_service/, puis les dépendances Python sont installées via le virtualenv dédié (ai_venv) avant le redémarrage du service.

workflow step
# Créer le répertoire si nécessaire
ssh ubuntu@51.91.253.146 \
  "mkdir -p /home/redboost/ai_service"

# Copier les sources Python
scp -i ~/.ssh/id_ed25519 -r \
  ai_service/* \
  ubuntu@51.91.253.146:/home/redboost/ai_service/

# Installer les dépendances et redémarrer
ssh ubuntu@51.91.253.146 \
  "/home/redboost/ai_venv/bin/pip install -r \
  /home/redboost/ai_service/requirements.txt \
  && sudo systemctl restart redboost-ai.service"

Déploiement manuel d'urgence

À utiliser uniquement si le pipeline est en panne. Suit les mêmes étapes que le workflow.

bash — urgence uniquement
# 1. Builder localement
cd redboost_backend && mvn clean package -DskipTests
cd ../redboost_frontend && npm ci && npm run build

# 2. Copier les artefacts
scp redboost_backend/target/*.jar ubuntu@51.91.253.146:/home/redboost/
scp -r redboost_frontend/dist/sakai-ng/* ubuntu@51.91.253.146:/var/www/html/
scp -r ai_service/* ubuntu@51.91.253.146:/home/redboost/ai_service/

# 3. Redémarrer les services
ssh ubuntu@51.91.253.146 "sudo systemctl restart redboost-prod.service"
ssh ubuntu@51.91.253.146 "/home/redboost/ai_venv/bin/pip install -r \
  /home/redboost/ai_service/requirements.txt \
  && sudo systemctl restart redboost-ai.service"
⚠️
Préférer toujours le pipeline — un build local peut embarquer des variables d'environnement de développement ou des dépendances non committées.

Checklist avant de merger sur main

  • Build local validé : mvn clean package -DskipTests et npm run build passent sans erreur
  • Aucune clé secrète dans le code — les 3 secrets (VPS_HOST, VPS_USER, VPS_SSH_KEY) sont dans GitHub Secrets
  • Nouvelles variables application.properties ajoutées manuellement sur le VPS avant de merger
  • spring.jpa.hibernate.ddl-auto sur validate en production (jamais update)
  • Swagger UI désactivé (springdoc.swagger-ui.enabled=false)
  • Vérifier l'onglet Actions GitHub après le push — tous les steps doivent être verts ✅
  • Tester l'URL de production une fois le pipeline terminé
